# Financial RC1 policy and evidence

All amounts, currency (MXN), recurrence and vehicle limits come from the server catalog. A pending checkout intent is reused across browser refreshes and new client keys until provider reconciliation closes it. Its provider idempotency key is persisted before the API call. A unique partial organization index enforces one active intent across all plans. A different plan returns PENDING_CHECKOUT_DIFFERENT_PLAN until the previous intent is reconciled/cancelled; it cannot start a second recurring charge. Historical attempts remain available for diagnosis.

Webhook signatures require the signed URL `data.id`, request ID, HMAC and a five-minute timestamp tolerance (seconds or milliseconds). Duplicate signed request IDs are acknowledged after processing. A new delivery still fetches the current provider resource. `subscription_preapproval`, `subscription_authorized_payment` and `payment` use their respective provider endpoints; payments must identify the preapproval. Missing correlation fails without entitlement changes. Retries after timeout/HTTP failure receive a non-success response.

Reconciliation correlates the exact provider subscription ID. It does not rewrite all previous attempts for an organization/plan. Older provider versions/timestamps and superseded attempts cannot replace valid state. Unknown statuses or inconsistent pricing preserve valid state and write a reconciliation-required audit. Documented preapproval states are authorized, pending, paused and cancelled. Pending authorization grants no entitlement.

`next_payment_date` is retained separately as `nextPaymentAt`; it is not proof of a paid period ending. Provider-managed entitlement follows reconciled authorization/cancellation, with failed/refunded/charged-back payments marking past due. A preapproval update alone does not clear a payment failure. Approved correlated payments require matching price/currency to recover access. Manual renewals extend from the later of now and the current paid expiry, using one UTC calendar month clamped to the destination month's last day.

Manual review requires an active platform-admin session with verified MFA, validated plan/amount/currency/period and tenant receipt verification at submission. Payment, subscription, organization and audit changes share one Mongo transaction. Repeated approval does not extend the period twice. A non-cancelled Mercado Pago subscription must be cancelled before manual activation to avoid an ongoing second charge.

Cancellation and plan changes use `PATCH /api/account/subscription`: billing permission, organization capacity lock, provider GET, provider PUT, provider GET confirmation, then a local Mongo transaction. A downgrade cannot exceed the new vehicle limit. Provider failure leaves local state intact. The requested-operation audit permits reconciliation if provider succeeds but local commit fails. Webhook reconciliation can recover that divergence.

Mongo replica-set support is mandatory; Atlas provides it. CI starts a disposable single-node replica set. There is no non-transactional fallback. Before rollout inspect legacy attempts, duplicate active subscriptions and model indexes; do not silently migrate financial history.

Evidence on 2026-09-30: real Atlas QA + namespaced Redis; provider calls stubbed. Regression coverage proves exact-attempt correlation, unknown-state preservation, separate next-payment date, stale replay rejection, provider 400/500/timeout, transaction rollback and same-event recovery, stale snapshot protection, calendar-month/idempotent manual approval, pending-intent reuse, provider-first cancellation and plan changes. Live provider scenarios remain an external production gate.
